⚠️ Contexte & Problématique
Pourquoi l'approche DevOps pour TaskFlow ?

Les Limites de l'Existant (Avant DevOps)

  • Cloisonnement Dev / Ops : « Chez moi ça marche » mais échec en production.
  • Déploiements manuels pénibles : Plusieurs heures, erreurs humaines fréquentes.
  • Tests oubliés : Pas de Quality Gate automatisé avant mise en ligne.
  • Opacité opérationnelle : Pas de visibilité sur les pannes ni les performances.

La Réponse TaskFlow

  • Microservices autonomes : Découplage complet User Service et Task Service.
  • Conteneurisation Docker : Environnement strictement identique dev/prod.
  • CI/CD automatisé : Déploiement en moins de 40 secondes à chaque git push.
  • Supervision temps réel : Métriques Prometheus et tableaux de bord Grafana.

🏗️ Architecture Globale de la Solution
Modèle 3-Tiers Microservices & API Gateway

Topologie Réseau & Rôles

  • Client Web (Navigateur) : Point d'accès unique sur le port 80.
  • Nginx Reverse Proxy : Sert le SPA Frontend et route /api/users et /api/tasks.
  • User Service : Port 3001 (Node.js/Express, /health, /metrics).
  • Task Service : Port 3002 (Node.js/Express, /health, /metrics).
  • Isolation Réseau : Réseau Docker Bridge interne.

   └── /api/tasks ──► [ Task Service :3002 ]
                             ▲
                             │ (Scrape /metrics 5s)
[ Grafana :3000 ] ◄── [ Prometheus :9090 ]

🔭 Bilan, Limites & Perspectives d'Avenir
Évolutions vers un produit d'Entreprise

Limites Actuelles

  • Hébergement sur une seule instance EC2 (SPOF matériel).
  • Session AWS Learner Lab limitée à 4 heures.
  • Stockage en mémoire pour le prototype actuel.

Perspectives d'Évolution

  • Kubernetes (K8s/K3s) : Auto-scaling horizontal (HPA).
  • Persistance relationnelle : PostgreSQL + Prisma sous AWS RDS.
  • Sécurité HTTPS : Certificats SSL automatiques Let's Encrypt.
  • Analyse Statique : SonarQube & alertes Alertmanager.
